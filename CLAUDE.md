## Чек-лист сверки с ТЗ

- [ ] Только фронтенд, без бэкенда и внешних API
- [ ] Состояние — через React Context (без Redux/Zustand и т.п.)
- [ ] Стили — только CSS Modules (`*.module.css`); глобально — лишь токены и reset в `src/index.css`
- [ ] Каждый компонент — своя папка в `src/components/<Name>/`: `<Name>.jsx` + `<Name>.module.css` (+ локальные хуки при необходимости)
- [ ] `src/hooks/` — только общие хуки; `src/utils/` — чистые функции без React
- [ ] Все числа вычислений — `bigint` (модель `Decimal`), никаких `Number`/`parseFloat` в расчётах
- [ ] История сохраняется в localStorage
- [ ] Есть переключение «обычный ↔ инженерный»
- [ ] Работаем по одной фиче за раз

## Принятые решения

- **Структура строго по ТЗ:** только `components/`, `hooks/`, `utils/`. Контекст (`createContext`) + хук — в `hooks/useX.js`,
  провайдер — компонент `components/XProvider/`. Папки `context/` нет.
- **Числа:** `{ value: bigint, scale: number }` (значение = value / 10^scale) — `src/utils/decimal/`.
  Разделение на целую/дробную часть — только для вывода (`toParts`), не для хранения.
- **Точность:** 34 значащие цифры (`PRECISION`) после каждой операции; целые — точно;
  целая часть > 1000 цифр — `OVERFLOW`; меньше 10^-1000 — ноль. Округление половины от нуля.
- **Математика F5** (`utils/decimal/math.js`): фиксированная точка на bigint с 10 запасными знаками;
  sin/cos/tan в градусах (кратные 90° — точно) и радианах; xʸ, √, n!, ln, log, π, e.
- **Ошибки:** `DecimalError` с `code` (`DIVISION_BY_ZERO`, `OVERFLOW`, `DOMAIN`) + `SYNTAX`; текст — только в UI.
- **Модель состояния:** выражение — список токенов, один движок (`utils/expression/evaluate.js`, shunting-yard)
  для обоих режимов; приоритет операций (2+3×4 = 14), неявное умножение (2π).
- **Набираемое число** — `InputNumber { digits: bigint, scale, hasDot, negative }`, тоже bigint.
- **Состояние:** `status: editing | result | error` вместо флагов; `evaluation.id` растёт с каждым "=".
- **% как в iOS:** `a ± b%` — b процентов от a, иначе b/100.
- **Экран:** до 16 значащих цифр, иначе экспонента (`utils/calculator/display.js`).
- **Тема:** CSS-переменные из Figma + `data-theme` на `<html>`.
- **Контексты:** state и dispatch разнесены по разным контекстам.
- **Приближённые результаты** (exp, дробные степени) округляются до 34 значащих цифр и в целой части
  (`roundSignificant`), чтобы не показывать «точные» выдуманные цифры.
- **Провайдеры** (`*Provider`) — компоненты без разметки, поэтому без `.module.css`.
- **История:** `calc:history` в localStorage, до 50 записей, числа строками; битые записи отбрасываются по одной.
  Запись — локальным хуком `useRecordEvaluation` по новому `evaluation`.
- **Настройки:** тема `calc:theme` (по умолчанию — тема ОС, сохраняется только после выбора пользователя;
  inline-скрипт в `index.html` убирает мигание), режим и единицы углов — `calc:settings`.
- **Клавиатура:** `utils/keyboard.js` (чистое отображение клавиш) + локальный хук `Calculator/useKeyboardInput.js`;
  инженерные клавиши ( ) ^ ! — только в инженерном режиме; в открытом диалоге истории не перехватывается.
- **Шрифт:** Work Sans 300/400 (`@fontsource/work-sans`, локально, без внешних запросов).
- **Адаптив:** одна колонка до 768px; высота кнопок зависит от высоты экрана — без прокрутки от 320×568.
- **Тесты:** Vitest (`npm test`), jsdom + Testing Library для компонентов; `vitest.setup.js` подставляет
  localStorage в памяти (Node ≥ 25 ломает jsdom-овский); линтер oxlint.

## Известные ограничения

- `ln(e)` внутри = 0.99…98 (34 знака, как и должно быть для 34-значного e); на экране — `1`.
- Углы чуть больше кратных 180° (`sin(180.0000000001°)`) — 32 верные цифры вместо 34.
